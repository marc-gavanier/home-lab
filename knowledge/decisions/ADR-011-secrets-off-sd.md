# ADR-011 — No secrets on the unencrypted SD card

**Date**: 2026-07-13
**Status**: accepted (deployed and verified on the Pi)

## Context

The homelab boots from an unencrypted SD card (full-disk encryption of the OS
was rejected: unattended reboots must reach SSH so the operator can unlock
LUKS remotely — see the boot-and-unlock runbook). An audit found cleartext
credentials on that card: the Docker `.env` (service admin/DB passwords),
`backup.env` (both restic repo passwords, rest-server credentials), the host
WireGuard private key, rclone WebDAV configs and the SearXNG `secret_key`.

Anyone who extracts or images the SD card could read them offline — and by
rewriting the WireGuard endpoint, join the VPN as the homelab host and read
the entire offsite backup repo. That bypasses exactly what LUKS protects on
the HDD, and mirrors the reasoning that got the account password hash locked
(ADR-009 line of work: the SD is readable, so nothing secret may live there).

## Decision

Credential-bearing files live in `/mnt/data/secrets/` on the LUKS volume;
the historical paths remain as **symlinks**, so scripts, systemd units and
docs are unchanged:

| Historical path                             | Real location (LUKS)                     |
|---------------------------------------------|------------------------------------------|
| `/opt/homelab/.env`                         | `/mnt/data/secrets/homelab.env`          |
| `/opt/homelab/backup.env`                   | `/mnt/data/secrets/backup.env`           |
| ~~`/opt/homelab/configs/searxng/settings.yml`~~ (see note) | `/mnt/data/secrets/docker/searxng_settings` |
| `/etc/wireguard/wg0.conf`                   | `/mnt/data/secrets/wg0.conf`             |
| claude rclone config                        | `/mnt/data/secrets/claude/rclone.conf`   |
| operator rclone config (`RCLONE_CONFIG`)    | `/mnt/data/secrets/<user>/rclone.conf`   |

> **Note (2026-07-27, issue #27)** — the SearXNG row is the one case where a
> symlink could not work, and it is worth stating as a limit of this decision.
> Every other entry here is resolved **host-side** (Ansible, systemd, or Compose
> reading `.env`). SearXNG's settings live inside a bind-mounted *directory*, so
> the container resolved the link in its own namespace, found nothing, and wrote
> a stub over it. That file is now bind-mounted directly, 0444 in the
> `/mnt/data/secrets/docker/` directory the Docker secrets use (ADR-016). The
> rule: a symlink is fine for host-side consumers, never for a path a container
> reads through a directory mount.

Units that consume these files are gated on the volume
(`RequiresMountsFor=/mnt/data`) and, when they must start at unlock rather
than at boot, pulled in by `mnt-data.mount` via `systemctl add-wants`
(wg-quick@wg0, vault-mount). Everything here only runs after `homelab-unlock`
anyway — the change costs nothing operationally.

`/mnt/data/secrets` is part of the restic backup set (the symlinked entries
under `/opt/homelab` are stored as symlinks, so the real files must be backed
up for disaster recovery to restore credentials).

## Accepted residuals (documented, not fixed)

- **Offsite Pi WireGuard key** stays on its SD: that host must reboot fully
  unattended (no LUKS by design, ADR-010). A stolen key joins the VPN but
  holds no rest-server credentials and no repo password; response is client
  revocation in wg-easy.
- **`/etc/killswitch.env`** stays on the SD: the kill switch must work
  *before* unlock — that is its purpose. Compromise yields only the ability
  to power the Pi off.
- **Kuma push token** inside the offsite health script (no encrypted storage
  exists on that host); worst case is forged monitor pings.
- **Claude/`.claude` OAuth tokens** in home directories: revocable.
- Boot-time essentials (SSH host keys, UFW rules, WG *server* config inside
  Docker on LUKS already) are out of scope by nature.

## Consequences

- A stolen or imaged homelab SD card yields configuration but **no
  credentials** — equivalent to the public GitHub repo.
- Recovery posture is unchanged: the system on the SD stays repairable
  offline; secrets are regenerated by Ansible from the vaults (or read from
  the LUKS disk, which opens on any machine with the passphrase).
- The WireGuard tunnel and the claude vault mount now appear only after
  `homelab-unlock` (they are pulled in by `mnt-data.mount`) — the nightly
  03:00 offsite copy is unaffected since backups need `/mnt/data` anyway.
- One-time cost: the first backup after the path-set change (adding
  `/mnt/data/secrets`) loses its parent snapshot and re-scans everything.
